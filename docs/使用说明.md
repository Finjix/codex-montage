# V20.2.5 FF版控制三件套

本目录独立于原剪映版。三部分依次为：V20语义分析包、FFmpeg控制器、FF完整执行器。

入口：`components/montage-three-part-orchestrator-ff/scripts/three_suite_ff.py`。

V20.2强制内容指纹、帧区间黑名单、当前任务证据、全帧边界、PCM/强制对齐、共享候选连坐和60fps编码后复检。生产渲染只接受 `source_in_frame`、`speech_end_frame`、`source_out_frame_exclusive` 和源帧率；只有秒数的计划直接失败，不存在时间裁切回退。

V20.2.4在原规则上新增“全文件夹回归门禁”：清洁/派生素材必须追溯到原片 SHA-256 和原始帧区间；用户判坏区间不能通过重命名、中间文件或新 candidate ID 绕过。每个候选由预期文本强制对齐确定首词，首词前最多保留3个原生帧，禁止用音轨波纹或能量阈值当作说话开始。最终回执升级为 `ffmpeg-post-encode-qc/v20.5`，强制 fresh ASR、完整话轮、前后词完整、无夹音/气口/瞬态。

V20.2.5新增：完整话轮内部纯气口可在用户明确授权后按原生帧压缩，但必须有强制对齐、零词交集、前后音节和连接词证据；切点满幅峰值只能做同帧区间均匀降幅后重检。最终控制器还必须接收编码后片头60帧视觉族发布回执，计划标签不能代替最终画面检查。

所有新制作和返修都必须从 FF 三件套执行器进入。用户判坏候选会连坐撤销全部依赖成片；禁止任务临时脚本直接改计划、直接渲染后手工替换交付目录。完整规则见 `components/semantic-analysis-training-backup-v20/references/wuzimu-v20-folder-regression-gate.md`。

吴樾批次的片头重复按“实际首镜头视觉族”统计，不按 candidate ID：同一视觉族最多3条，片头+第二段视觉组合最多2条；40条必须先证明至少14个合格片头视觉族。

- `components/semantic-analysis-training-backup-v20/scripts/frame_range_repair.py`

- `components/ffmpeg-montage-controller/scripts/boundary_signal_scan.py`
- `components/semantic-analysis-training-backup-v20/scripts/winky_ledger.py`
- `runtime-lock.json`：上述文件及FFmpeg/FFprobe的版本哈希锁。

帧计划与夹帧修复示例见 `references/frame-native-rendering-v20.2.md` 和 `references/frame-plan.example.json`。生成器不能直接写通过；最终完成必须同时具备语义、帧计划、FF控制器和独立后编码终检回执。
